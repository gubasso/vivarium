# 13 — Doctor and health checks

The contract for `viv doctor`: the shared probe catalog, severity and status model, flags, output shapes, and exit codes. The governing decisions are [`../../decisions/ADR-0023-doctor-check-catalog-and-contract.md`](../../decisions/ADR-0023-doctor-check-catalog-and-contract.md) (this contract), [`../../decisions/ADR-0022-config-inspection-namespace.md`](../../decisions/ADR-0022-config-inspection-namespace.md) (`doctor` is a pure checker — it never renders configuration; that is `viv config`'s job), and [`../../decisions/ADR-0015-cli-output-and-failure-contract.md`](../../decisions/ADR-0015-cli-output-and-failure-contract.md) (streams, `--json`, sysexits).

`viv doctor` diagnoses; it changes nothing. It is read-only, side-effect-free, and never modifies project, config, or VM state. One probe catalog serves three call sites: `doctor` runs the whole catalog, each command's preflight guard runs its hard subset before any side effect ([`10-vm-lifecycle.md`](./10-vm-lifecycle.md)), and setup flows reuse individual probes — so the checks can never drift apart.

## Severity, scope, and status

Each check carries three classifications:

- Severity — `hard` or `soft`. Hard checks form the preflight subset: a hard failure makes `viv start` (and a cold-starting `exec`/`shell`) refuse before any side effect. Soft checks only warn. There is no per-invocation waiver of a hard check — a check that could legitimately be ignored is soft by definition, so preflight remains an unconditional guarantee.
- Scope — `host` (always runnable), `project` (needs a selected manifest), or `network` (needs `--online`). Out-of-scope checks are skipped, never failed.
- Status (per run) — `pass`, `warn` (a soft check tripped), `fail` (a hard check tripped), or `skipped` (out of scope, with a reason). Skips never affect the exit code.

## Check catalog

Stable kebab-case ids; catalog order is cheapest-and-most-fundamental first, so the earliest failure is the most actionable.

### Hard — host scope (the preflight subset)

| Id                        | Category       | Passes when                                                                                                                         | Failure code |
| ------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| `nix-present`             | tooling        | `nix` is on `$PATH`                                                                                                                 | `69`         |
| `nix-version`             | tooling        | Nix meets the minimum version — the latest stable release at decision time (2.34); the implementation pins the exact floor          | `69`         |
| `nix-flakes-enabled`      | tooling        | `nix` can read a flake: `experimental-features` names both, or a two-line probe flake is read                                       | `78`         |
| `kvm-device-present`      | virtualization | `/dev/kvm` exists                                                                                                                   | `69`         |
| `kvm-device-accessible`   | permissions    | the user can read and write `/dev/kvm`                                                                                              | `77`         |
| `hardware-virt-available` | virtualization | CPU virtualization extensions are present and enabled                                                                               | `69`         |
| `host-userns-available`   | permissions    | unprivileged user namespaces are available — the per-share filesystem daemon's namespace sandbox (N20) cannot be built without them | `69`         |
| `runtime-dir-usable`      | permissions    | `$XDG_RUNTIME_DIR` names an absolute path that exists, is owned by the user, and is not group- or world-accessible                  | `77`         |

`kvm-device-present` and `kvm-device-accessible` are split because remediation differs: enable virtualization in firmware vs join the `kvm` group. `host-userns-available` is hard rather than soft because the N20 profile is by-construction and unwaivable: a host that cannot provide the namespace sandbox cannot launch at all, and failing at preflight is far more actionable than failing mid-launch.

`runtime-dir-usable` is hard for the same shape of reason and is the one check with no degraded mode at all: the runtime root has no fallback, so a host without it cannot hold a VM's lock, control socket, or pid file ([`02-config-and-xdg-layout.md`](./02-config-and-xdg-layout.md), [`../../decisions/ADR-0055-runtime-directory-is-required.md`](../../decisions/ADR-0055-runtime-directory-is-required.md)). It covers four distinct faults — unset or empty, not absolute, absent or unwritable, and wrong owner or mode — and its message names the variable and which of the four tripped, because the repairs are different and a generic "runtime directory unavailable" throws away the whole value of failing loudly. Being hard already scopes it correctly: only the ensure-running routine runs the preflight subset, so `viv config` and `viv status`, which need no runtime root, are unaffected.

Nix is the only tool this catalog looks for on the host. The hypervisor, its control client, and every filesystem daemon arrive in the built runner's closure, pinned by the project's lockfile, so their presence and version are settled at build time rather than probed ([`../../decisions/ADR-0049-backend-is-a-closure-member.md`](../../decisions/ADR-0049-backend-is-a-closure-member.md)). That decision draws the line this catalog now follows: `viv doctor` probes host conditions only; anything the lockfile determines is an evaluation-time assertion, not a check.

| `store-roots-intact`       | disk           | at least one VM is running and some path in that guest's system closure is no longer present in the host store — the host store is an overlay lower layer inside the guest, so a path collected or deleted under a running guest leaves the overlay's behaviour undefined. Conditioned on a running VM for the reason `host-linger` is: with nothing running there is nothing to corrupt. The generation the VM booted from already pins that closure against collection (N14), so a finding here means something outside a root's reach removed the path — a direct deletion, or a collection of something the pin does not cover. Running on invocation stands, and the presumption behind it is measured: the realistic hazard — a guest resolving a path it is not already holding open — is loud, and no read ever returned corrupt bytes, so a user does reach for `doctor` with a symptom in hand rather than with an unexplained fault. What is quieter is narrower than "silent": a process already holding the file open keeps reading correct bytes, which is not a correctness fault ([`06-workspace-and-project-environment.md`](./06-workspace-and-project-environment.md), [`../microvm-verification-harness.md`](../microvm-verification-harness.md), [`../../decisions/ADR-0085-a-running-guest-pins-the-store-paths-it-reads.md`](../../decisions/ADR-0085-a-running-guest-pins-the-store-paths-it-reads.md)) |
| `host-linger`              | permissions    | at least one VM is running and the host does not keep the user's session manager alive across logout, so those VMs will not survive the user's final logout. Conditioned on a running VM deliberately: lingering is off by default on most hosts, and warning about it with nothing to lose would be noise ([`10-vm-lifecycle.md`](./10-vm-lifecycle.md), [`../../decisions/ADR-0056-vm-lifetime-bounded-by-user-session.md`](../../decisions/ADR-0056-vm-lifetime-bounded-by-user-session.md))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

`state-manifest-orphans` is soft because retained state is not itself a host defect and may be intentional. A renamed or removed manifest makes the state unreachable through ordinary workspace resolution, so the probe supplies the early visibility ADR-0054 preserves while leaving deletion to an explicit operator judgment. Being soft keeps it out of the launch preflight subset.

### Soft — project scope (skipped when no manifest is selected)

| Id                             | Category | Warns when                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `config-parses`                | config   | the selected manifest does not parse. Parse only — `doctor` never evaluates or renders the merge; that is `viv config eval`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `manifest-resolves`            | config   | the precedence chain does not resolve to exactly one defined manifest, including when two manifests claim the working directory as a workspace                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `working-directory-declared`   | config   | the working directory does not lie inside a directory the resolved manifest declares as a workspace (ADR-0109, [`06-workspace-and-project-environment.md`](./06-workspace-and-project-environment.md)). Reports the finding every manifest-resolving command refuses on, naming the resolved manifest file, the undeclared directory, and the exact `[[workspaces]]` block to add ([`03-artifact-model.md`](./03-artifact-model.md))                                                                                                                                                                                                                                                                                                                                    |
| `shared-layer-paths-portable`  | config   | a shared image or piece in the resolved composition declares a literal personal path where a portable variable belongs (N11, [`07-secrets-and-config-sharing.md`](./07-secrets-and-config-sharing.md)). A textual lint over the declarations — like `config-parses` it never evaluates, so it is only an early warning; the authoritative check runs at evaluation and returns `65` ([`../../decisions/ADR-0042-evaluation-time-content-defects.md`](../../decisions/ADR-0042-evaluation-time-content-defects.md))                                                                                                                                                                                                                                                      |
| `manifest-no-inline-secret`    | config   | a manifest `[env]` value looks like a credential. The manifest's text is compiled into the generated flake and therefore lands in the world-readable store, so an inline token is a build-time secret whatever its channel (N10, [`07-secrets-and-config-sharing.md`](./07-secrets-and-config-sharing.md)). A heuristic textual lint, sibling of `shared-layer-paths-portable` — deliberately best-effort, so a value it does not flag is not a promise that the value is safe; the guarantee it supports lives in [`16-logging-and-diagnostics.md`](./16-logging-and-diagnostics.md) ([`../../decisions/ADR-0069-redaction-is-by-construction.md`](../../decisions/ADR-0069-redaction-is-by-construction.md))                                                          |
| `mount-source-not-session-dir` | config   | a declared mount `source` textually resolves under the host's `/tmp`, `/var/tmp`, or `${XDG_RUNTIME_DIR}` (N24, [`06-workspace-and-project-environment.md`](./06-workspace-and-project-environment.md)). A textual lint of the same family as `shared-layer-paths-portable`: it never evaluates and never expands, so a source that only becomes a session path after host-side expansion is invisible to it — the authoritative refusals are `65` at evaluation and `78` at launch                                                                                                                                                                                                                                                                                     |
| `lock-covers-declared-inputs`  | config   | a shared image or piece in the resolved composition declares a flake input the effective lock carries no node for ([`03-artifact-model.md`](./03-artifact-model.md), [`04-composition-and-determinism.md`](./04-composition-and-determinism.md)). A name comparison between the declarations and the lock in force — it resolves nothing and touches no network, so it stays inside the offline default. The message names the lock in force, because that decides the remedy: `viv update` under the tool-owned lock, and the team's own act under an override ([`02-config-and-xdg-layout.md`](./02-config-and-xdg-layout.md)). Soft because the build path already refuses at `78` with the precise message, so this buys early visibility rather than a second gate |
| `agent-source-usable`          | config   | the composition declares an agent channel whose host source is not usable: for `ssh`, `$SSH_AUTH_SOCK` unset, naming a path that does not exist, not a socket, or not owned by the user; for `gpg`, no resolvable restricted extra socket ([`07-secrets-and-config-sharing.md`](./07-secrets-and-config-sharing.md)). The message names which of those faults tripped, because "unset", "missing", "wrong type", and "wrong owner" have four different repairs. The probe stops at the socket's existence and ownership — it never connects, and never asks an agent to sign or decrypt, because `doctor` changes nothing                                                                                                                                               |

Ambiguous ownership is reported by both `manifest-resolves` and `working-directory-declared`, and it is the one condition where a project-scope probe reports without a selected manifest: two manifests claiming the directory means there is no single project to gather, so skipping with `no-manifest-bound` would say the opposite of what happened.

`working-directory-declared` is the second consumer of one refusal routine, and it is the only probe that reports a condition another command refuses outright. That asymmetry is the decision rather than an inconsistency: `viv start`, `viv exec`, `viv shell`, `viv stop`, `viv status`, `viv destroy`, `viv volume`, and the `config` readers all fail fast at `78` through the routine, while `doctor` consumes the same finding and teaches it. A `doctor` that exited `78` on the very condition it exists to explain would be self-defeating, and being soft is also what keeps it out of the launch preflight subset — the preflight's own path already refuses.

`agent-source-usable` is soft, and that follows from the severity rule above rather than from leniency: a user who starts a VM to run tests that need no key has legitimately waived it, which is the definition of soft. It buys early visibility before the launch path refuses a declared channel that cannot be satisfied at all. `--strict` already gives CI the fail-on-warn behavior, so no new lever is needed.

One neighbouring fault is deliberately not a check: whether a mount source resolves to a socket or another special file. That needs the fully expanded source and the descriptor the share will be served from, neither of which exists before launch, so it is a launch-time refusal ([`06-workspace-and-project-environment.md`](./06-workspace-and-project-environment.md)) rather than a probe — the same membership rule that keeps closure-owned properties out of this catalog. Nothing in this table ever reads a secret, a credential value, or an agent's traffic; the redaction contract holds here by construction ([`16-logging-and-diagnostics.md`](./16-logging-and-diagnostics.md)).

Two properties of the project's own guest are deliberately absent from this table: whether the guest kernel carries the balloon driver that makes declared memory a ceiling (N22), and whether each share names a cache policy the shipped daemon accepts. Both are settled by the composition and the lockfile, so both are evaluation-time assertions returning `65`, not probes ([`../../decisions/ADR-0049-backend-is-a-closure-member.md`](../../decisions/ADR-0049-backend-is-a-closure-member.md), [`../../decisions/ADR-0042-evaluation-time-content-defects.md`](../../decisions/ADR-0042-evaluation-time-content-defects.md)). Neither ever reads the declared memory figure, which is launch-channel and never a build input (N19).

When no manifest declares the current workspace, `doctor` still runs every host-scope check, notes once on stderr that project-scope checks are skipped, and marks each as `skipped` / `no-manifest-bound`. All host checks passing still exits `0`.

### Soft — network scope (skipped unless `--online`)

| Id                         | Category | Warns when                                                                                                                                                                                                                                                                        |
| -------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `nix-version-currency`     | network  | the installed Nix trails the latest stable release                                                                                                                                                                                                                                |
| `substituter-reachability` | network  | a configured substituter is unreachable                                                                                                                                                                                                                                           |
| `egress-allowlist-dns`     | network  | an allowlisted hostname does not resolve — probed only when the selected manifest sets `sandbox.egress.mode = "allowlist"` (also project scope). Distinct from a denied host, whose fail-fast contract is owned by [`05-networking-and-egress.md`](./05-networking-and-egress.md) |

`egress-allowlist-dns` is the only place an unresolvable allowlisted name surfaces, and that is a deliberate division of labour: allowlisted names are resolved lazily, when the guest asks, so a name that upstream cannot answer never blocks a launch and never turns into a vivarium error. It is a finding here, and an upstream `NXDOMAIN` or `SERVFAIL` to the guest there. Only a wildcard-free entry can be probed — a `*.`/`**.` pattern names no single host to look up — so a manifest of nothing but wildcards yields no finding rather than a false one.

The default run is fully offline. Open egress is not a check and never renders as a finding — it is policy, not a health defect (N8, [`05-networking-and-egress.md`](./05-networking-and-egress.md)).

### Guaranteed by construction (not probed)

Some facts about a launch are settled by how vivarium builds and launches, not by any host condition a probe could observe — the boundary [`../../decisions/ADR-0049-backend-is-a-closure-member.md`](../../decisions/ADR-0049-backend-is-a-closure-member.md) draws for the whole catalog. Two of them are security properties: the separate guest kernel (N1) and the host-side sandbox around the VMM and every virtiofsd (N20). vivarium's launch wrapper enacts N20 as a fixed hardened launch profile, so the confinement cannot be disabled at runtime ([`../../decisions/ADR-0027-vmm-and-virtiofsd-hardening-launch-profile.md`](../../decisions/ADR-0027-vmm-and-virtiofsd-hardening-launch-profile.md)):

- VMM (Cloud Hypervisor). Launched unprivileged with `PR_SET_NO_NEW_PRIVS`, capabilities dropped toward zero, built-in seccomp enabled (`--seccomp true`), a Landlock path allowlist where the kernel supports it, and placement in the target's host resource scope ([`17-resources-and-capacity.md`](./17-resources-and-capacity.md)). The memory arguments the elastic model requires — shared guest memory, a zero-size balloon with free page reporting and deflate-on-OOM, and a per-VM control socket — are part of the same fixed profile.
- virtiofsd (one process per share). Launched unprivileged, `--sandbox=namespace`, the identity-translation arguments that map the fixed guest user to the invoking host user and forbid every other guest identity ([`06-workspace-and-project-environment.md`](./06-workspace-and-project-environment.md), [`../../decisions/ADR-0066-share-uid-gid-translation.md`](../../decisions/ADR-0066-share-uid-gid-translation.md)), seccomp enabled with the killing action — a logging or trapping action would leave the filter advisory and void N20 — with only its own share writable, never as root and never `--sandbox none`, the configuration behind the guest-root-to-host-root escape CVE-2026-47243. Unprivileged execution also costs each daemon the capability that would let it reference inodes by handle, so it falls back to holding one open descriptor per referenced inode against a limit it cannot raise for itself — a whole-tree walk therefore pins one descriptor per file in the tree, per share, which is the scale the ceiling has to cover. The wrapper therefore declares each daemon's descriptor limit on its own arguments rather than letting it inherit the session's hard limit, so the budget does not vary by host ([`../../decisions/ADR-0093-the-share-descriptor-budget-is-declared.md`](../../decisions/ADR-0093-the-share-descriptor-budget-is-declared.md)). Every daemon joins the same scope as the VMM, so a stopped VM leaves none behind. A share's cache policy is coherency, not confinement, and is named per share in [`06-workspace-and-project-environment.md`](./06-workspace-and-project-environment.md); the daemon's worker-pool size is performance for the same reason, and is pinned there to one value uniform across shares. Both are asserted at evaluation but are no part of this guarantee.
- QEMU fallback is documentation-only — admissible under N2 but not hardened; use Cloud Hypervisor for untrusted workloads.

Several of the values this profile fixes are also the upstream defaults today, and stating them anyway is the point: a guarantee that rests on an inherited default is one an upstream release can withdraw without a diff in this repository. The wrapper therefore names every value it depends on, whether or not it currently differs from the default.

These are guarantees of construction; `viv doctor` probes only the host prerequisites (the soft-host checks, including `host-landlock-available`), never whether the sandbox "is on." See [`08-invariants-and-guarantees.md`](./08-invariants-and-guarantees.md) and [`../../decisions/ADR-0024-backend-security-requirements.md`](../../decisions/ADR-0024-backend-security-requirements.md).

## Flags

```text
viv doctor [--json] [--strict] [--list] [--online]
```

- `--json` — one machine record on stdout (shape below).
- `-v` / `--verbose` — the global verbosity flag (see [`01-command-surface.md`](./01-command-surface.md) "Global flags"); on `doctor` it surfaces deeper per-check detail (observed versions, paths, permissions, free bytes).
- `--strict` — any `warn` fails the run: exit `1` (the one sanctioned use of `1`, per the ADR-0023 amendment to ADR-0015). For CI gates.
- `--list` — enumerate the catalog (id, category, scope, severity, title) without running any probe; combines with `--json`.
- `--online` — enable the network-scope checks. There is no `--offline`; offline is the default.

Color and TTY behavior follow ADR-0015 (`NO_COLOR > FORCE_COLOR > isatty`); there is no per-command color flag.

## Exit codes

Codes draw from the program-wide taxonomy in [`14-exit-codes.md`](./14-exit-codes.md); `doctor` maps its outcomes onto it as:

| Outcome                                                        | Exit                                   |
| -------------------------------------------------------------- | -------------------------------------- |
| No hard check failed (warns and skips allowed)                 | `0`                                    |
| Hard failure(s) — first failing check in catalog order decides | that check's code (`69` / `77` / `78`) |
| `--strict` and at least one `warn` (no hard failure)           | `1`                                    |
| Internal error in `doctor` itself                              | `70`                                   |

## Output

The report is the command's result: human report or `--json` record on stdout; progress and the skip note on stderr, so `viv doctor --json 2>/dev/null | jq` is always clean (ADR-0015).

Human output groups by category, uses bracketed word markers — never unicode glyphs — and ends with a summary line naming the exit:

```text
tooling
  [pass]     nix-present              nix 2.18 on PATH
  [fail]     nix-version              nix 2.18, minimum 2.34
                 hint: upgrade nix to 2.34 or newer, then re-run viv doctor
  [pass]     nix-flakes-enabled       nix-command flakes

disk
  [warn]     nix-store-disk-space     8.3 GB free (warn under 10 GB)
                 hint: reclaim space with viv gc

config
  [skipped]  manifest-resolves        no manifest declares this workspace

4 pass - 1 warn - 1 fail - 1 skipped -> exit 69
```

`--json` emits one enveloped record:

```json
{
  "status": "fail",
  "checks": [
    {
      "id": "nix-version",
      "category": "tooling",
      "scope": "host",
      "severity": "hard",
      "status": "fail",
      "message": "nix 2.18, minimum 2.34",
      "hint": "upgrade nix to 2.34 or newer, then re-run viv doctor",
      "doc_url": "/doctor/checks/nix-version"
    },
    {
      "id": "manifest-resolves",
      "category": "config",
      "scope": "project",
      "severity": "soft",
      "status": "skipped",
      "reason": "no-manifest-bound"
    }
  ],
  "summary": { "total": 7, "passed": 4, "warned": 1, "failed": 1, "skipped": 1, "hard_failures": 1 },
  "schema_version": "1"
}
```

- `reason` appears only on skipped checks (`no-manifest-bound`, `offline-mode`, `not-applicable`).
- `doc_url` is optional and omitted when no page exists — never emitted as null — so consumers test key presence and pages can ship incrementally. The path scheme is stable and predictable: `/doctor/checks/<id>`; the host is bound when the documentation site exists.
- `summary.hard_failures` lets scripts gate without re-deriving severity from the array.

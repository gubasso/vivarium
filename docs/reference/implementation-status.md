# Implementation status

The single source of truth for what vivarium does today versus what is designed only. The specification under [`spec/`](spec/README.md) describes the intended design; this page records how much of it exists in code.

## Current state: a manifest boots, and a command runs inside it

The Nix-built diagnostic runner now hands a strict launch contract to the Rust [policy constructor](../../src/launch/policy.rs), [transient-service renderer](../../src/launch/systemd.rs), and [supervisor](../../src/launch/supervisor.rs). The supervisor implements API create-before-boot ordering, one daemon per share, console ownership, group cancellation, allowlisted runtime cleanup, a current-boot agent ping, and initial credential-pool readiness. The shared [protocol](../../src/protocol/mod.rs) and private [guest agent](../../crates/vivarium-guest-agent/src/main.rs) implement bounded framing, process and PTY sessions, guest AF_VSOCK listeners, and declared SSH/GPG relays.

The first public commands now run. [`../../src/config/registry.rs`](../../src/config/registry.rs) maintains the rebuildable cache-root workspace index, [`../../src/config/resolve.rs`](../../src/config/resolve.rs) keeps the filesystem-free precedence decision, and [`../../src/cli/`](../../src/cli/) resolves the selected manifest from a flag, the environment, or unique declared workspace ownership. `viv config` and the `manifest` readers expose that result without writing into a workspace.

Evaluation now runs. A selected manifest compiles to a generated flake carrying vivarium's own [option surface](../../nix/vivarium-options.nix) and [report expression](../../nix/vivarium-report.nix), [`../../src/config/evaluate.rs`](../../src/config/evaluate.rs) evaluates it through Nix and installs the pin the first evaluation creates, and [`../../src/config/merged.rs`](../../src/config/merged.rs) reads the result into effective values, provenance, and content defects. `viv config eval` renders the merge and refuses a defect with `65`; `viv config sources` renders the same defect and exits `0`. The shipped [example manifest](../../examples/manifests/rust-web.toml) evaluates to a guest system derivation, which [`../../tests/host/guest-system-check`](../../tests/host/guest-system-check) builds on a capable host. The `ConfigEval` gate is open on a host with Nix that can reach the pinned flake inputs, and its three trials pass.

Booting now runs. The generated flake composes vivarium's own [guest module](../../nix/guest.nix) and publishes the same runner the diagnostic path executes, so a manifest-built guest and the shipped image are one guest reached two ways; [`../../src/cli/lifecycle.rs`](../../src/cli/lifecycle.rs) turns that into `viv start`, `viv status`, and `viv stop`, keyed by the selected manifest name. The `Virtualization` gate is open on a host with `/dev/kvm` and a systemd user manager, and the two trials this slice names pass unskipped there.

Reaching into the guest now runs. [`../../src/launch/control.rs`](../../src/launch/control.rs) carries the host end of the wire protocol whose guest half slice 003 proved, [`../../src/cli/lifecycle.rs`](../../src/cli/lifecycle.rs) adds the ensure-running routine spec/12 fixes — the per-target `flock`, a cheap `Ping`, the `boot.json` identity match, and the same cold-start path `viv start` owns rather than a second one — and [`../../src/cli/session.rs`](../../src/cli/session.rs) turns both into `viv exec` and `viv shell`. A guest command's status comes back verbatim, host environment passthrough is deny-by-default against a fixed allowlist, and an interactive shell gets a PTY sized before it starts, job control, resize forwarding, and a host terminal restored on every exit path including a signal.

Workspaces are mounted and proved. Every tree a manifest declares in `[[workspaces]]` appears inside the same guest at the absolute path it occupies on the host ([ADR-0108](../decisions/ADR-0108-a-workspace-is-owned-by-one-manifest.md), [ADR-0110](../decisions/ADR-0110-the-workspace-is-an-ordinary-mount.md)); it reaches the guest as an ordinary declared mount whose target is its own expanded source, so there is one sharing mechanism and the guest holds no notion of a workspace. The refusals — a path the guest owns, and two trees that nest — are decided when the manifest is resolved, before any evaluation, by every command that resolves one. `workflow_09_workspace_round_trip` proves ownership translation for one tree. `workflow_20_many_workspaces_one_sandbox` boots two disjoint trees in one VM, round-trips both, reuses that VM from either tree, and proves `exec` and `shell` preserve the invoking root or subdirectory exactly. A command resolving a selected manifest now refuses an undeclared working directory with `78`; doctor reports the same finding and continues. `[[mounts]]` remains the non-owning surface for a chosen guest target, and is now the same surface a workspace compiles into: each mount becomes its own confined share, expands against the host at launch, and is refused before boot when it is unset, missing, not a regular file or directory, or a session directory. A regular-file source reaches the guest without its neighbours through its own staged export root ([ADR-0105](../decisions/ADR-0105-a-file-mount-is-staged-into-its-own-export-root.md)). Keeping data across a restart also works now, and did not before: `viv stop` was destroying the VM rather than powering the guest down, so anything the guest had not committed was lost — measured, fixed in the supervisor's teardown ladder and in the transient unit's `KillMode`, and re-measured with an unsynced write surviving twice.

The surface that reports and removes that data now runs too. `viv volume list` joins three sources — the two volumes that exist without being declared, what the merged configuration declared, and what is on disk — and reports each one's declaring layer, whether it is an orphan, and what its sparse image occupies against its ceiling; `viv volume prune` removes exactly the orphans that list surfaces and nothing else; and `viv destroy` walks the same teardown ladder `viv stop` does and removes manifest-keyed state and, unless retained, volumes while leaving the workspace, manifest, and pinned lockfile alone. A manifest's `[[volumes]]` is no longer inert: a declared volume becomes its own disk, mounts where the declaration asked, and is owned by the session user on its first boot.

A build now roots itself. Every successful build appends a numbered generation to the per-project profile spec/11 fixes — a symlink registered as a garbage-collector root, with the record and the whole lock in force retained beside it — so an ordinary collection costs dead paths rather than a cold rebuild, which is the defect Q-023 measured before this surface existed. `viv generations list` names what is retained, `activate` and `rollback` move the `current` pointer, `prune` unlinks exactly what its retention argument selects and refuses the running VM's own generation at `75` from the boot record, `viv start --generation <n>` boots a retained build without evaluating, and `viv gc` performs the whole-store sweep it used to only parse — reclaiming exactly what no root pins, proved with a canary beside a held build by [`tests/host/generations-check`](../../tests/host/generations-check).

The fleet is visible. `viv status` fills the measured half spec/17 defines — the scope's own memory charge beside the declared ceiling, the volume images' occupancy against their apparent sizes, the scope's pressure share, and the agent's own count of attached sessions, read over the control protocol's query pair and `null` wherever a reading is honestly unavailable — and `viv status -g` enumerates every manifest-keyed sandbox with retained state as one row carrying its declared workspace set, with the host's own reading beside the fleet and a vanished workspace directory named on stderr and never removed. Measured per-sandbox memory needs the memory controller delegated to the user manager; where it is not, the figure reports as unavailable and `host-cgroup2-delegation` names the shortfall.

The stop ladder is whole. `viv stop` opens with [`spec/10-vm-lifecycle.md`](spec/10-vm-lifecycle.md)'s first rung — the shutdown request pair the control protocol now carries (`0x10`/`0x11`), which the guest agent answers by handing the request to the guest's own service manager through a root-owned path unit and acknowledging that the shutdown is in motion — and the operator's `--timeout` bounds that orderly ask, which is what the flag was written for. An unreachable agent, an agent that predates the request, or a boot record another version wrote all degrade to the backend's power signal under the remainder of the same grace; a guest that acknowledged and then wedged is handed to the power path's compiled window before the group is killed, so its cleanup still runs. `viv stop --all` applies the same ladder to every running sandbox from any directory, attempts every one, and reports the first failure after the sweep finishes; both verbs emit the `--json` records [`spec/01-command-surface.md`](spec/01-command-surface.md)'s lifecycle section fixes.

The guest has a network, and both egress modes are enforced. [`spec/05-networking-and-egress.md`](spec/05-networking-and-egress.md)'s shape is the one that runs: every VM's network lives in its own host-side user+net namespace pair, held open by a pinned `unshare` and joined by pid, with a tap the VMM opens by name and one unprivileged `pasta` per VM as the uplink — the supervisor's [spawn order](../../src/launch/supervisor.rs) is holder, forwarding sysctl, tap, filter, uplink, resolver, VMM-in-namespace. Under `open`, the default, the guest reaches what the host reaches, with the uplink's DNS forward as its nameserver; measured in a booted guest on 2026-08-14, a route via the tap gateway, working name resolution, and an HTTPS 200 from `cache.nixos.org`. Under `allowlist`, the default-deny ruleset and the allowlist's literal destinations are in the kernel before any packet path exists, and [the gating resolver](../../src/net/resolver.rs) — the only DNS the guest is given — releases an answer only after its addresses are installed with the record's TTL as their lifetime; measured the same day, a denied name answered `REFUSED` in 9 ms and a denied literal TCP connect reset in 15 ms. `workflow_05_restrict_egress_allowlist` holds the whole contract against a hermetic in-namespace fixture — two `.test` names on different addresses, `REFUSED` distinguished from `NXDOMAIN` at the resolver — and `profile.pre-push` is plain `kind(test)` again. What the subsystem does not yet carry: IPv6 addressing on the guest link (the resolver withholds AAAA for exactly that reason, which is spec/05's rule for a host without a working IPv6 path). The `egress-allowlist-dns` health finding spec/13 names now runs under `viv doctor --online`.

The verb's two former gaps are closed. `viv start` runs [`spec/17-resources-and-capacity.md`](spec/17-resources-and-capacity.md)'s admission check between preflight and anything it would create: below the reserve it refuses at `69` under `host.memory-reserve` with nothing built and no lock taken (`workflow_26_admission_refusal` demonstrates the absence under a crafted `/proc/meminfo` bind), on fleet overcommit it warns on stderr and proceeds, and where the memory controller is not delegated it reaches its decision from host-level readings rather than skipping. `--attach` streams the console capture — the same file the supervisor tees — with `SIGINT` detaching at `0` and the VM left running (`workflow_26_start_attach_stream`). One residual is recorded rather than built: attaching to a sandbox that is already running, which [`spec/10-vm-lifecycle.md`](spec/10-vm-lifecycle.md)'s design permits, stayed out of slice 026's scope, so the attached form answers in words instead of streaming. `viv doctor` still surfaces retained state and data whose manifest is absent, preserving ADR-0054's report-rather-than-reap judgment beside the fleet view. The resource ceilings a launch applies are real: a manifest's `[resources]` wins, and an undeclared knob resolves from the host by spec/17's auto-sizing rule.

One more is quiet in the same way, and it belongs to the volume surface. A volume's ceiling cannot be raised after its image exists: spec/06 permits raising one between boots and never lowering it, and provisioning creates an image only when none is there, so a `size_gib` a manifest increases changes the launch contract and not the disk — the guest keeps the filesystem the first boot made, and `viv volume list` reports the image's own length, which is the ceiling actually in force rather than the declared one.

The human face now runs. `viv --help`, `viv <verb> --help`, and `viv --version` exist, and the global `-v`/`--verbose` and `-q`/`--quiet` are lifted before verb dispatch so placement is free (`ADR-0026`); [`../../src/ui/`](../../src/ui/) resolves one face per invocation from the stream facts, the environment, the verbosity, and the output mode, so progress animates only on a stderr terminal and never under `--json` or `-q`. Color follows the first-party `NO_COLOR > FORCE_COLOR > isatty` chain per stream, the diagnostic skeleton renders through a palette whose colored form strips back to the plain one byte for byte, and the long child runs — evaluation, build, render, boot — stream their stderr live under `-v` while capturing it complete for the diagnostic `why` slots. `viv start` wears the clack gutter end to end on a terminal, `viv stop` ticks its elapsed wait including under `--timeout -1`, and the data commands print dim-labeled, width-aligned records. `ADR-0103` owns the split; slice 016 carried it.

The doctor now runs, whole. All 31 probes of the [spec/13](spec/13-doctor-and-health-checks.md) catalog live in one registry ([`../../src/doctor/`](../../src/doctor/)) that serves both call sites: `viv doctor` reports every probe with bracketed word markers grouped by category, the `--json` envelope carries `summary.hard_failures` and `schema_version`, `--strict` promotes a warn to the one sanctioned exit `1`, `--list` enumerates without probing, `--online` admits the three network probes, and `viv start`'s preflight runs the same hard subset in the same order with the probe id as the diagnostic id — replacing the one-off `/dev/kvm` check it used to carry. The textual lints are best-effort by contract, and `agent-source-usable` reports the four spec/13 faults against every channel a shared layer's text declares, staying soft because the launch path refuses at `78` with the precise message.

What is no longer merely written is the credential relay, on both halves. `tests/guest_agent_host.rs` passes on a capable host, twice, driven by [`../../tests/host/guest-agent-check`](../../tests/host/guest-agent-check): real guest boot, AF_VSOCK transport on both ports, guest PTY job control and pre-`Start` sizing, boot-identity refusal that executes nothing, socket ownership and modes under `/run/vivarium`, opaque credential bytes, and pool refill under more concurrent clients than the pool has slots. The refill needed a backend at or above cloud-hypervisor v53.0 and no vivarium code ([KI-0002](./known-issues/resolved/KI-0002.md)). Figures and host in the [verification harness](./microvm-verification-harness.md). The host hop that made the relay reachable landed with slice 031: `viv start` resolves each declared id's host socket, refuses an unusable one at `78` before build and boot naming which fault tripped, and carries the resolved pair to the launch — `workflow_23_agent_channel_relay` proves the round trip as the user, a real host agent's key listed from inside the guest with no private key material anywhere the guest can read.

## Surface status

Each command sits at one of three levels:

- Designed — specified, with nothing written against it yet.
- Acceptance test written (gated) — a trial in [`../../tests/user_workflows.rs`](../../tests/user_workflows.rs) encodes the intended behavior and is linked below, and the behavior the row names does not run. Some of these commands do have a passing usage trial: their grammar and their fail-closed answer are real, and only the work behind them is missing. That is not enough for the top level, which is about the command doing its job, so the row stays here and its Trial column says which half is covered. A written trial is a specification made executable, not evidence that anything works.
- Implemented — the command runs and its trial passes.

The user owns the image. A directory-form selected image may carry a real `flake.nix` beside its module, and the generated flake takes it as an input named after the image, following each baseline the base declares — the user's `nixpkgs` is the guest's, the kernel's, and the hypervisor's ([ADR-0112](../decisions/ADR-0112-the-selected-image-carries-the-base-flake.md)). `viv update` is the pin-moving verb spec/01 fixes: it refuses under a team override naming both files, decides unknown names itself at `64`, updates a followed baseline through the base that owns its node, runs Nix against a private tree with the owned lock as reference and a staged sibling as output, validates the composed result before the replacing rename, and reports each public row's before and after with movement decided over the row's whole resolved subtree. [`tests/host/update-check`](../../tests/host/update-check) reads the moved component from inside the booted guest, twice.

Twenty-two rows are at `Implemented`. Every other public command is designed only.

## Stability

This page says what works. This section says what a release may change, which is the reader's other question and belongs beside the first.

Before 1.0, the minor component is the breaking axis. A patch release — `0.x.y` to `0.x.y+1` — must not break a documented invocation, a `--json` field, an exit code's meaning, or accepted manifest syntax. Breaking changes land only in a new minor, each named in the release notes with a migration example. Where practical a surface is deprecated for one minor first; an immediate break is reserved for security, correctness, and any surface that never reached Implemented above. Decided in [`../decisions/ADR-0075-pre-1.0-cli-stability-and-deprecation-policy.md`](../decisions/ADR-0075-pre-1.0-cli-stability-and-deprecation-policy.md).

Three surfaces are already permanent, now, pre-1.0 — earlier decisions made them so, and this promise does not weaken them:

- the exit-code taxonomy — never reassigned, append-only ([`spec/14-exit-codes.md`](spec/14-exit-codes.md));
- the compatibility messages and all five parts each must carry — file, failing position, unknown key, accepted key set, CLI version. Manifests carry no schema version, so these messages are the compatibility surface rather than a courtesy ([`spec/14-exit-codes.md`](spec/14-exit-codes.md)).

Diagnostic ids are stable and never reassigned, and are still not a branch surface — a consumer that must branch branches on the exit code. Both halves hold together; neither implies the other.

Outside the promise: human stderr prose beyond those normative messages and their rendering slots, additive `--json` fields, and the generated flake's internal shape, which is a regenerable cache artifact.

There is no experimental-feature gate before 1.0. At `0.x` the whole surface is unstable, so a per-feature gate would add a second stability vocabulary saying what the version number already says; the three levels above already stop a written-but-skipped trial from reading as a promise. A gate is the post-1.0 answer, if it is ever the answer.

## How to update this page

A command moves from Designed to Acceptance test written (gated) when a trial encodes its behavior — name the trial, and say plainly if the coverage is partial. It moves to Implemented only when the command runs and that trial passes unskipped; link the code that enacts it then. Any change that adds, removes, or renames a command, or changes its acceptance test, updates that command's row in the same change.

Keep this page honest: a reader deciding whether to rely on a feature consults it first, and a stale "Implemented" here is worse than none. Because the stability promise above leans on this table, honesty here is a checked obligation rather than a good intention. Three checks enforce it, and they belong in CI rather than in review:

1. every trial named in the Trial column resolves to a test that exists — this catches a rename;
2. no row claiming Implemented names a trial that the runtime gate skips or that is ignored — this catches the exact lie the paragraph above calls worse than none;
3. every subcommand the argument parser defines has a row here — this catches a command that shipped without a status.

The middle level exists precisely so a written-but-skipped trial cannot be mistaken for working software. This page owns status; the spec owns the contract. When a trial and the spec disagree about that contract, [`../../AGENTS.md`](../../AGENTS.md) carries the resolution rule — and a fact a trial is the only record of belongs in the spec page that owns it, not in the test file. Which lane a given trial belongs to, and what that lane proves, is in [`testing-lanes.md`](./testing-lanes.md).

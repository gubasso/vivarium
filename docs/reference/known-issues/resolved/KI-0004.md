# KI-0004 — the crate did not package, so vivarium left crates.io

- Status: `resolved` on 2026-11-11.
- Severity: medium — `cargo install vivarium` was unavailable for v0.2.0 and v0.2.1, and crates.io kept 0.1.0 as the latest version.
- External system: Cargo, which leaves a nested package out of its parent's tarball.
- Affected checks: `cargo package`, and the `package-check` step of `rk setup check`.
- Mask: removed. `.release-kit/config.toml` sets `profile.release.registry = "crates-io"`, and `release-plz.toml` sets `publish = true` with no `git_only`.

## Symptom

`cargo package` failed at its verification step. `build.rs` reported `NotFound` for `crates/vivarium-guest-agent`, because the packaged tree had no `crates/` directory. Measured 2026-09-09, and recorded in [Q-039](../../../plan/open-questions.md).

## Root cause

Cargo leaves out of a package every directory that carries its own `Cargo.toml`, and an explicit `include` changes nothing. `crates/vivarium-guest-agent` was a workspace member, so Cargo left it out. `build.rs` embeds the guest-agent source, because the guest-agent derivation builds from it, so the verification build of the packaged crate could not find it. A crate published past that check would fail to build for every user.

The mask was `publish = false` with `git_only = true` in `release-plz.toml`, and `registry = "none"` in `.release-kit/config.toml`. release-plz then read the last release from the `v*` tags and published nothing.

## Deployed fix and proof

Commit 71217d7 made the agent the `vivarium-guest-agent` binary of the `vivarium` package, behind a `guest` feature, as [`ADR-0115`](../../../decisions/ADR-0115-the-guest-agent-is-a-binary-of-the-crate.md) records. No nested package exists, so the packaged crate carries every file that `build.rs` embeds.

Proof, 2026-11-11: `cargo package --locked` packaged 139 files of v0.2.1 and compiled them, and `rk setup check` reported `package-check` as `satisfied`. Because crates.io held only 0.1.0, release-plz refused to leave git-only mode while the tag `v0.2.1` existed, so v0.2.1 was published by hand from its tag. v0.2.2 was released to GitHub alone before the registry answer changed, so it was published by hand from its tag too. After that, release-plz 0.4.3 reported the crate as up to date. Later releases publish through `.github/workflows/release-plz.yml` with crates.io trusted publishing.

## Recurrence signal

`rk setup check` reports `package-check` as failed, or `cargo package --locked` fails at verification. The likely cause is a new directory with its own `Cargo.toml` whose files `build.rs` embeds. Keep every embedded source inside the `vivarium` package.

# KI-0005 — v0.2.0 is a tag with no GitHub release, because dist built for macOS and Windows

- Status: `resolved` on 2026-11-11.
- Severity: medium — v0.2.0 has no GitHub release, no binaries, and no installer. The tag exists, and crates.io never carried the version, because of [`KI-0004`](./KI-0004.md).
- External system: cargo-dist 0.34.0, through the generated `.github/workflows/release.yml`.
- Affected checks: the `build-local-artifacts` jobs of the Release workflow, run [42942864133](https://github.com/gubasso/vivarium/actions/runs/42942864133).
- Mask: none. The fix removes the cause, and an old tag cannot be rebuilt.

## Symptom

release-plz merged the v0.2.0 release request on 2026-11-11 and pushed the tag `v0.2.0`. The tag push started the Release workflow. The two Linux builds passed, and the three other builds failed to compile:

- `aarch64-apple-darwin` and `x86_64-apple-darwin`: "error[E0599]: no associated function or constant named `PATH` found for struct `OFlags`".
- `x86_64-pc-windows-msvc`: "error[E0433]: cannot find `unix` in `os`".

The `host` job needs every build job, so it was skipped, and dist created no GitHub release.

## Root cause

vivarium runs only on Linux. It boots every guest behind KVM, and its code uses Linux-only interfaces, for example `rustix::fs::OFlags::PATH` in `src/launch/supervisor.rs` and `std::os::unix`. `dist-workspace.toml` still listed five targets, and three of them were macOS and Windows. No earlier release reached the dist build, so the list was never exercised.

A rerun of the Release workflow for `v0.2.0` fails the same way, because the `plan` job reads `dist-workspace.toml` of the tagged commit. `v0.2.0` therefore stays a git-only tag.

## Deployed fix and proof

`dist-workspace.toml` lists only `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu`, and it generates only the shell installer. The PowerShell installer served only Windows, so it is gone as well. `deny.toml` checks the dependency graph of the same two targets. v0.2.1 is the first release built from this configuration, and the first Linux-only release.

## Recurrence signal

The `dist-plan` job of `.github/workflows/ci.yml` runs `dist plan` on every pull request, but it does not compile the targets. A target that the code cannot build shows only in the Release workflow, as a failed `build-local-artifacts` job. Before a target is added to `dist-workspace.toml`, the code MUST compile for it.

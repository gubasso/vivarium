# vivarium documentation

Index into the project's four documentation zones. Each zone is a reader promise, not a topic bucket. This page is only an index — it holds no canonical facts of its own.

## Zones

- **[`reference/spec/`](reference/spec/README.md)** — the **product contract**: what vivarium is and does. Goals and non-goals, the command surface, the XDG config layout, the image/piece/manifest artifact model, composition and determinism, networking and egress, the workspace and inner project environment, secrets and config sharing, the normative invariants, the glossary, and the resource-and-capacity model that lets several sandboxes share one host.
- **[`decisions/`](decisions/)** — lean ADRs recording the durable _why_ behind the architecture: the isolation boundary, the module system as the composition engine, the artifact model, the manifest format, the config layout, manifest binding, egress policy, layer separation, workspace path handling, secrets, config being read-only to the tool (binding in state), generating config examples from types, the VM lifecycle and `viv start` semantics, build generations pinned as GC roots, the CLI output-and-failure contract, guest control transport and exec/shell exit boundary, the workspace mount path plus extra mounts, the lifecycle verbs and stop/destroy teardown boundary, the persistent volume model, the mount/config-mirroring schema, the CLI implementation baseline (the dependency choices, error/exit-code realization, and the logging stack), the elastic-resource set (guest memory as a ceiling, host scoping and admission control, sparse volumes, guest store sharing, and share cache policy), the sharing boundary that keeps the manifest personal while images and pieces carry a team's guarantees, the per-option classification that puts resource ceilings on the launch channel and volumes on the build channel, the rule making an evaluation-time content defect a hard error that the provenance viewer still renders, the identity marker's lifecycle across `start` and `destroy`, host-side egress enforcement with fail-fast denials, how a bare identifier in a manifest resolves to a file in the config library, the global config file and the precedence chain it sits in, the choice to give the manifest no schema version, the split that takes only guest-side system configuration from upstream while vivarium owns the launch itself, and the rule that makes the virtualization backend a member of the built closure rather than a host dependency to be probed. `template.md` is the drop-in ADR shape.
- **[`reference/`](reference/)** — lookup material beyond the spec: [`implementation-status.md`](reference/implementation-status.md) is the single source of truth for what works today versus what is designed only.
- **[`guides/`](guides/)** — task walkthroughs: [`getting-started.md`](guides/getting-started.md) walks the intended end-to-end flow, and eight per-task how-tos each pair with an acceptance trial that encodes the same sequence. Getting a project running: [`first-time-bind-boot.md`](guides/first-time-bind-boot.md) binds a manifest and boots for the first time, [`clean-repo-global-registry.md`](guides/clean-repo-global-registry.md) does it without putting anything in the repository. Shaping what the VM contains: [`team-shared-personal-overrides.md`](guides/team-shared-personal-overrides.md) layers a personal override over a team-shared config, [`inspect-before-run.md`](guides/inspect-before-run.md) reads the merged result before anything boots, [`restrict-egress-allowlist.md`](guides/restrict-egress-allowlist.md) narrows network access to a named list. Working and tearing down: [`run-agent-command.md`](guides/run-agent-command.md) runs a command in the guest and gets its exit status back, [`stop-restart-preserving-volumes.md`](guides/stop-restart-preserving-volumes.md) stops and resumes without losing work, [`destroy-cold-rebuild.md`](guides/destroy-cold-rebuild.md) tears a project down to a clean first run.
- **[`explanation/`](explanation/)** — the mental model: [`architecture.md`](explanation/architecture.md) explains the sandbox-vs-project-environment split and how the pieces fit together.
